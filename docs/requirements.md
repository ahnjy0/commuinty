# 모바일 웹 커뮤니티 서비스 요구사항 정의서

## 0. 개요

| 항목 | 내용 |
|---|---|
| 서비스 형태 | 모바일 웹(반응형), 하단 탭 네비게이션 |
| 하단 탭 | 홈(피드) / 내 정보(프로필) / 설정 |
| 기술 스택 | Next.js, Supabase, Tailwind CSS, Vercel |
| 인증 방식 | Supabase Auth (이메일/비밀번호) |
| 데이터/스토리지 | Supabase Postgres, Supabase Storage(프로필 이미지) |

## 2. 기능별 상세 요구사항

### FR-01 회원가입
- 입력 항목: 이메일, 비밀번호, 비밀번호 확인, 닉네임
- 이메일 형식 검증, 비밀번호 최소 8자 이상
- 닉네임 중복 확인 (프로필 테이블 기준)
- 가입 성공 시 `profiles` 테이블에 기본 프로필 레코드 생성
- 가입 완료 후 자동 로그인 → 홈 피드로 이동
- 실패 시 에러 메시지 표시 (이메일 중복, 비밀번호 불일치 등)

### FR-02 로그인
- 입력 항목: 이메일, 비밀번호
- Supabase Auth 세션 발급, 로그인 성공 시 홈 피드로 이동
- 로그인 실패 시 (이메일/비밀번호 불일치) 에러 메시지 표시
- 비로그인 상태에서 글 작성/댓글/좋아요 시도 시 로그인 화면으로 유도

### FR-03 로그아웃
- 설정 탭 내 로그아웃 버튼
- Supabase 세션 종료 후 로그인 화면(또는 홈 비로그인 상태)으로 이동
- 로그아웃 확인 다이얼로그 노출

### FR-04 글 작성
- 입력 항목: 제목(선택 또는 미사용, 커뮤니티 성격에 따라 본문 위주 가능), 본문(필수, 텍스트)
- 이미지 첨부는 1차 범위 제외(추후 확장 여지), 텍스트 기반 글쓰기 우선
- 로그인한 사용자만 작성 가능
- 작성 완료 후 목록/상세로 이동
- 본문 최소/최대 글자 수 제한 (예: 1자 이상 2,000자 이하)

### FR-05 글 목록 조회 (피드)
- 홈 탭 진입 시 전체 글을 최신순으로 노출
- 목록 아이템: 작성자 닉네임/프로필 이미지, 본문 일부(요약), 작성 시각, 좋아요 수, 댓글 수
- 무한 스크롤 또는 페이지네이션으로 목록 로딩
- 비로그인 사용자도 목록 조회 가능(읽기 전용)

### FR-06 글 상세 조회
- 목록에서 글 선택 시 상세 화면 진입
- 상세 내용: 작성자 정보, 본문 전체, 작성 시각, 좋아요 수, 댓글 목록
- 본인 글일 경우 수정/삭제 버튼 노출 (기본 CRUD 범위 포함)

### FR-07 댓글 작성/조회
- 상세 화면 하단에 댓글 목록 및 입력창 노출
- 로그인한 사용자만 댓글 작성 가능
- 댓글: 작성자 닉네임, 본문, 작성 시각
- 최신순 또는 등록순 정렬 (등록순 권장)
- 본인 댓글은 삭제 가능

### FR-08 좋아요
- 글 상세/목록에서 좋아요 버튼 토글
- 로그인한 사용자만 좋아요 가능, 사용자당 글 1회만 허용
- 좋아요 수는 실시간(또는 액션 시점) 반영
- 이미 좋아요 누른 글은 상태 표시(하이라이트)

### FR-09 내 프로필 조회/수정
- 내 정보 탭에서 닉네임, 프로필 이미지, 자기소개(선택) 확인
- 프로필 이미지는 Supabase Storage 업로드, 미설정 시 기본 이미지 사용
- 닉네임 수정 시 중복 검사
- 저장 시 `profiles` 테이블 갱신

### FR-10 내가 쓴 글 목록
- 내 정보 탭에서 본인이 작성한 글 목록 노출 (최신순)
- 각 글 클릭 시 상세 화면으로 이동
- 목록에서 삭제 가능(선택)

### FR-11 다른 유저의 프로필 보기
- 목록/상세 화면에서 작성자 닉네임 또는 프로필 이미지 클릭 시 해당 유저 프로필 화면 진입
- 노출 정보: 닉네임, 프로필 이미지, 자기소개, 해당 유저가 작성한 글 목록
- 타인 프로필에서는 수정 버튼 미노출

### FR-12 설정
- 로그아웃 버튼
- (확장 여지) 비밀번호 변경, 계정 탈퇴, 알림 설정 등의 진입점 자리 확보
- 앱 정보(버전 등) 노출 가능

## 3. 사용자 흐름

### 3.1 신규 사용자 온보딩
1. 앱 접속 → 홈(비로그인 상태, 글 목록 열람 가능)
2. 글 작성/좋아요/댓글 시도 → 로그인 필요 안내 → 로그인 화면 이동
3. 계정 없음 → 회원가입 화면 이동
4. 이메일/비밀번호/닉네임 입력 후 가입 → 자동 로그인 → 홈 피드 진입

### 3.2 로그인 사용자의 글 작성 흐름
1. 홈 탭에서 글쓰기 버튼 클릭
2. 본문 입력 후 등록
3. 등록 완료 → 글 상세 또는 홈 피드로 이동 → 목록 최상단에 반영

### 3.3 글 상세 열람 및 상호작용 흐름
1. 홈 피드에서 글 선택 → 상세 화면 진입
2. 좋아요 버튼 클릭 → 즉시 카운트 반영
3. 댓글 입력 → 등록 → 댓글 목록 하단(또는 최신 위치)에 반영
4. 작성자 프로필 클릭 → 해당 유저 프로필 화면 이동

### 3.4 내 프로필 관리 흐름
1. 내 정보 탭 진입 → 닉네임/프로필 이미지/내가 쓴 글 목록 확인
2. 프로필 편집 진입 → 닉네임/이미지 수정 → 저장
3. 내가 쓴 글 목록에서 글 선택 → 상세 이동, 필요 시 수정/삭제

### 3.5 로그아웃 흐름
1. 설정 탭 진입
2. 로그아웃 버튼 클릭 → 확인 다이얼로그
3. 확인 시 세션 종료 → 홈(비로그인 상태)으로 이동

## 5. 데이터 개요 (Supabase 테이블 초안)

### profiles
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK, FK → auth.users.id) | 사용자 식별자 |
| nickname | text (unique) | 닉네임 |
| avatar_url | text (nullable) | 프로필 이미지 URL (Storage) |
| bio | text (nullable) | 자기소개 |
| created_at | timestamptz | 생성 시각 |

### posts
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 글 식별자 |
| author_id | uuid (FK → profiles.id) | 작성자 |
| content | text | 본문 |
| created_at | timestamptz | 작성 시각 |
| updated_at | timestamptz | 수정 시각 |

### comments
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 댓글 식별자 |
| post_id | uuid (FK → posts.id) | 대상 글 |
| author_id | uuid (FK → profiles.id) | 작성자 |
| content | text | 댓글 내용 |
| created_at | timestamptz | 작성 시각 |

### likes
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid (PK) | 좋아요 식별자 |
| post_id | uuid (FK → posts.id) | 대상 글 |
| user_id | uuid (FK → profiles.id) | 좋아요 누른 사용자 |
| created_at | timestamptz | 생성 시각 |

- `likes`는 (post_id, user_id) 조합에 unique 제약 → 중복 좋아요 방지
- 글/댓글 삭제 시 하위 데이터(댓글, 좋아요)는 CASCADE 삭제 정책 적용 고려
- Storage 버킷: `avatars` (프로필 이미지 저장, 공개 읽기 권한)
